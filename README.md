# WC Tracker — HKT Ground Handling

ระบบบันทึกการให้บริการรถเข็น (Wheelchair Service) สนามบินภูเก็ต
Google Apps Script Web App + Google Sheets

## ไฟล์

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `Code.gs` | Backend (Apps Script) — API flights / cases / assign, บันทึก TripLog, สรุป DailySummary |
| `Index.html` | หน้าเว็บแอป (มือถือ) — LP จ่ายงาน · Porter กดเริ่ม/จบงานของตัวเอง |

## ไฟล์ Google Sheets ที่เชื่อมต่อ

1. **Daily Flight Schedule Record 2026** (`FLIGHT_SS_ID`)
   — ตารางบิน tab รายเดือน (`AUG2026`, `SEP2026`, ...) ใช้ดึงรายการไฟลท์ของวันนี้
2. **MMM YYYY PORTER SUMMARY** (`PORTER_SS_ID`)
   — ไฟล์ assign case ของ OCC/VIP (tab รายวัน) ใช้:
   - ดึงเคสที่ assign วันนี้มาแสดงในแอป (เที่ยวบิน, porter, WCHR/WCHS/WCHC, gate, ETA/ETD)
   - เขียนเวลา **รับเคส** (ตอนกดเริ่ม) และ **ส่งเคส** (ตอนกดจบ) กลับไปที่ชีทอัตโนมัติ
     (เขียนเฉพาะช่องที่ยังว่าง — ไม่ทับข้อมูลที่กรอกเองแล้ว)
   - ไฟล์นี้เปลี่ยนทุกเดือน → `PORTER_AUTO_BY_NAME = true` จะหาไฟล์เดือนปัจจุบัน
     จากชื่อไฟล์ใน Drive ให้อัตโนมัติ (fallback เป็น `PORTER_SS_ID`)
3. **MMM YYYY PRE-WHEELCHAIR** (`PRE_SS_ID`, โฟลเดอร์รายเดือนใน `PRE_ROOT_FOLDER_ID`)
   — ไฟล์ของ LP (tab รายวัน `01SEP26`…) มี 3 บล็อกที่ระบบใช้:
   - **ยอดจองล่วงหน้ารายไฟลท์** — WCHR/WCHS/WCHC/AVIH/MAAS แยกขาเข้า-ขาออก + C/T open-close
   - **จำนวนเคสแต่ละช่วงเวลา** (ทุก 2 ชม.) และ **MANPOWER** (SKED/OT) ช่วงเดียวกัน
   - **Porter Daily Assignment** — ตารางเวรจริง: ชื่อ, เข้า-ออก, OT เข้า-ออก, รหัสลา (OFF/SL/BL)
4. **WC Tracker Log** — ไฟล์ที่ผูกกับ Apps Script นี้
   (TripLog + DailySummary + Queue + WCStatus + AssignLog)

## ระบบใหม่ v5.0 — แยกบทบาท LP / Porter

v4.0 ทุกคนเห็นหน้าจอเดียวกันและต้องเลือกชื่อตัวเองใหม่ทุกครั้ง
v5.0 แอปถามครั้งเดียวว่า "คุณคือใคร" แล้วจำไว้ในเครื่องนั้น — LP กับ porter
เห็นคนละหน้าจอ และการจ่ายงานเกิดขึ้นในแอปได้เลย ไม่ต้องสลับไปเปิดชีท

### เปิดแอปครั้งแรก

เลือกบทบาท เก็บไว้ใน `localStorage` ของเครื่องนั้น กดปุ่ม **เปลี่ยน** บนแถบด้านบน
เพื่อสลับได้ตลอด

| บทบาท | เห็นอะไร |
|---|---|
| 👔 **LP / หัวหน้างาน** | หน้าหลัก · 🎯 จ่ายงาน · ทีม · คิว · สรุป |
| 👷 **Porter / พนักงาน** | 🎫 งานของฉัน · ภาพรวม · ทีม · คิว · สรุป |

Porter ต้องเลือกชื่อตัวเองจากรายชื่อ (คนที่ขึ้นเวรวันนี้ลอยขึ้นบนสุด) แอปจะจำรหัส
พนักงานไว้ แล้วใช้ตาราง `ROMAN` แปลงเป็นชื่ออังกฤษอย่างที่สะกดใน Porter Summary
เพื่อหาว่าเคสไหนเป็นของตัวเอง

### 🎯 หน้าจ่ายงาน (LP)

- รายการเคสวันนี้ พร้อมตัวกรอง **ยังไม่จ่าย / ทั้งหมด / กำลังทำ / เสร็จแล้ว**
  (เริ่มที่ "ยังไม่จ่าย" เพราะนั่นคือสิ่งที่ต้องทำ)
- กด **จ่ายงาน** → เลือกคนจากรายชื่อที่ **เรียงตามเคสค้างน้อยสุดขึ้นก่อน**
  (กติกาเดียวกับคิว) แต่ละคนแสดง `เคสค้าง/เคสรวม` และกะที่ขึ้นเวร
- เลือกได้หลายคนในเคสเดียว (เคสที่ต้องใช้ 2 คน) — เขียนลงชีทเป็น `"A, B"`
- กด **บันทึก** → เขียนชื่อกลับเข้าช่อง "ชื่อพนักงาน" ของ Porter Summary ทันที
  และตั้งสถานะเป็น `STANDBY` ให้ถ้ายังว่างอยู่
- กด **เปลี่ยนคน** บนเคสที่จ่ายไปแล้ว — ติ๊กคนเดิมไว้ให้ ถอนออกได้ (ล้างช่องชื่อ)
- **เปิดเคสใหม่จากตารางบิน** — เลือกไฟลท์จาก Daily Flight Schedule แล้วเลือกคน
  ระบบจะเขียนลงแถวว่างที่มีเลข "ที่" อยู่แล้วในชีทวันนี้

ทุกครั้งที่จ่ายงานจะบันทึกลงชีท `AssignLog` ของไฟล์แอป (ใครจ่ายเคสไหนให้ใคร
เปลี่ยนจากใคร เมื่อไหร่) — ไม่ไปยุ่งกับ Porter Summary

**กติกาความปลอดภัยฝั่ง server** (แอปเดาเองไม่ได้):

| สถานการณ์ | ผลลัพธ์ |
|---|---|
| เคสส่งผู้โดยสารแล้ว (มีเวลาส่งเคส) | เปลี่ยนคนไม่ได้ — ชื่อในชีทคือคนที่ทำจริง |
| เคสกำลังให้บริการอยู่ (มีเวลารับเคส) | เพิ่มคนช่วยได้ แต่ถอดคนที่ทำอยู่ออกไม่ได้ |
| แถวในชีทถูกแทรก/ลบหลังแอปโหลดข้อมูล | หาแถวใหม่จาก IATA + เที่ยวบิน + เลข "ที่" ให้เอง |
| หาแถวไม่เจอจริง ๆ | ไม่เขียนมั่ว — แจ้งให้รีเฟรชแล้วจ่ายใหม่ |
| ชีทวันนี้ไม่มีแถวว่างให้เปิดเคสใหม่ | แจ้งให้เพิ่มแถวในชีทก่อน (ไม่แทรกแถวเอง เพราะจะดันบล็อก STAFF RECORD) |

### 🎫 หน้างานของฉัน (Porter)

- นับ **กำลังทำ / รอเริ่ม / เสร็จแล้ว** + กะของตัวเองจากตารางเวรจริง
- **กำลังให้บริการอยู่** — การ์ดพร้อมตัวจับเวลาสด และปุ่ม **จบงานนี้**
- **รอเริ่มงาน** — เคสที่ LP จ่ายให้ เรียงตามเวลาไฟลท์ (ขาออกใช้ ETD ขาเข้าใช้ ETA)
  แต่ละใบบอก gate, SSR, เวลาที่ได้รับแจ้ง และถ้าเป็นเคสที่ทำคู่กันจะบอกว่าทำกับใคร
- กด **เริ่มงานนี้** → ข้ามหน้าเลือกคน ไปเลือกรถเข็นเลย (เป็นตัวเราเสมอ)
- บนหน้า "ภาพรวม" porter กดได้เฉพาะเคสของตัวเอง — กดของคนอื่นจะเตือนแทนที่จะเริ่มงานให้

### งานที่ค้างอยู่ไม่หาย

เดิมงานที่กำลังทำเก็บไว้ในหน้าเว็บเท่านั้น — รีเฟรช ปิดแอป หรือมือถือดับ = หาย
v5.0 อ่านงานที่ยังไม่จบจาก `TripLog` ฝั่ง server (`?action=active` และมากับ `board` ด้วย)

- รีเฟรชหน้าจอแล้วงานที่ค้างกลับมาพร้อมตัวจับเวลาที่เดินต่อจากเวลาเริ่มจริง
- เริ่มงานบนเครื่องหนึ่ง ไปกดจบบนอีกเครื่องได้
- อีกเครื่องกดจบไปแล้ว รอบโหลดถัดไปงานจะหายจากหน้าจอนี้เอง
- `handleStart` กันเริ่มซ้ำ: รถเข็นที่มีคนใช้อยู่ หรือเคสที่ตัวเองเริ่มไปแล้ว จะถูกปฏิเสธ
  พร้อมบอกว่าใครใช้อยู่ตั้งแต่กี่โมง — แอปจะถอนงานออกจากหน้าจอให้แทนที่จะโชว์ค้างไว้

### สถานะเคสในชีทอัปเดตเอง

`markCase()` เขียนกลับเข้า Porter Summary ตอนกดเริ่ม/จบ:

| กด | เขียนอะไร |
|---|---|
| เริ่มงาน | ติ๊ก "รับเคส" + เวลารับเคส + สถานะ `ON PROCESS` |
| จบงาน | เวลาส่งเคส + สถานะ `COMPLETED` |

สถานะไม่ถอยหลัง (`COMPLETED` แล้วไม่กลับไป `ON PROCESS`) และไม่แตะเคสที่ถูก
`CANCELLED` ช่องเวลาที่กรอกไว้แล้วไม่ถูกเขียนทับ

### API ที่เพิ่มมา

| เรียก | ได้อะไร |
|---|---|
| `GET  ?action=active` | งานที่ยังไม่จบทั้งระบบ (จาก TripLog) |
| `GET  ?action=myjobs&sid=&name=` | เคสของ porter คนเดียว + งานที่กำลังทำ |
| `POST {action:'assign', assign:{...}}` | จ่าย/เปลี่ยน/ถอนคนของเคสหนึ่ง |
| `POST {action:'case_new', case:{...}}` | เปิดเคสใหม่จากไฟลท์ |

`?action=board` มี `active` เพิ่มเข้ามาด้วย — หน้าจอยังโหลดครั้งเดียวจบเหมือนเดิม

### ทดสอบ (รันใน Apps Script editor)

| ฟังก์ชัน | เช็คอะไร |
|---|---|
| `testActive()` | งานที่ยังค้างอยู่ตอนนี้ |
| `testMyJobs()` | การจับคู่ชื่อ porter กับเคสในชีท (แก้ชื่อในฟังก์ชันก่อนรัน) |
| `testFreeCaseRows()` | ชีทวันนี้เหลือแถวว่างให้เปิดเคสใหม่กี่แถว |

### ชีทที่เพิ่มในไฟล์แอป

`AssignLog` — `บันทึกเมื่อ · วันที่ · แถวในชีท · เคส · เที่ยวบิน · SSR · จ่ายให้ · คนเดิม · จ่ายโดย · หมายเหตุ`

`TripLog` เพิ่ม 3 คอลัมน์ท้ายตาราง: `Case Row · Case Airline · Case Flt`
(ใช้หาแถวเคสตอนกดจบงานจากอีกเครื่อง — ชีทเดิมที่มีอยู่แล้วใช้ต่อได้ แถวเก่าปล่อยว่างไว้)

## ระบบใหม่ v4.0 — Ops Control

ระบบเดิมรู้แค่ "เคสที่เกิดแล้ว" v4.0 เพิ่มมิติ **งานที่กำลังจะมา** และ **กำลังคนจริง**

### API เดียวจบ
`GET ?action=board` คืนทุกอย่างที่หน้าแอปต้องใช้ในรอบเดียว (เคส + ตารางเวร +
ยอดจอง + demand/manpower + คิว + สถานะรถเข็น) แต่ละแหล่งพังได้อิสระ —
ที่เหลือยังแสดงผลต่อได้ และรายงานใน `errors`
API แยกยังใช้ได้: `?action=pre` · `?action=roster` · `?action=cases` ·
`?action=summary` · `?action=queue` · `?action=wcstatus`

### หน้าหลัก — แถบ "ช่วงเวลานี้"
ช่วง 2 ชม. ปัจจุบัน: งานที่จองไว้ (เข้า/ออก) · คนเข้าเวรตอนนี้ · กำลังบริการ
พร้อมป้ายภาระงาน **รับไหว / ค่อนข้างแน่น / งานหนัก** (เทียบ demand ÷ SKED+OT)

### แท็บ "👥 ทีม" ใหม่ — ตารางเวรจริง
- จัดกลุ่มตามกะจริงจากชีท (`07:00-16:00`, `15:00-03:00`, `17:00-05:00` …)
  ไม่ใช่ A/B/C สมมติอีกต่อไป
- ไฮไลต์คนที่ **เข้าเวรอยู่ตอนนี้** (คำนวณรองรับกะข้ามเที่ยงคืน) และป้าย OT
- แยกรายชื่อ ลา/วันหยุด พร้อมรหัส (OFF/SL/BL)

### คิว
- ชิป **"🟢 เข้าเวรตอนนี้"** + ชิปรายกะจริง
- ปุ่ม **"เติมคิวจากตารางเวร"** ดึงคนจาก Porter Daily Assignment เข้าคิว
  พร้อมยอดเคสสะสมจากชีท (เรียงคนเคสน้อยสุดขึ้นก่อนเหมือนเดิม)

### สรุป
เพิ่ม **จองล่วงหน้า vs เกิดจริง** (ส่วนต่าง), ตาราง **งานจอง vs กำลังคนต่อช่วงเวลา**
(เคส/คน — เกิน 1.2 ขึ้นแดง, ไฮไลต์ช่วงปัจจุบัน) และ **ไฟลท์ที่มียอดจองล่วงหน้า**

### ทดสอบ
`testPre()` — ตารางเวร + demand/manpower + ช่วงเวลาปัจจุบัน ·
`testSummary()` · `testCases()` · `testStaff()` · `listPorterTabs()`


## สรุปเคส + สถานะจริงจากชีท (v3.5)

อ้างอิงโครงสร้างจริงของ **SEP 2026 PORTER SUMMARY** (แท็บรายวัน `01SEP26`…`14SEP26`)

- **สถานะเคสจากชีทโดยตรง**: `STANDBY` (ยังไม่เริ่ม) / `ON PROCESS` (กำลังทำ) /
  `COMPLETED` (จบแล้ว) — ไม่ต้องเดาจากเวลาอีก (ถ้าช่องสถานะว่างจึงค่อย fallback)
- **1 เคสมีหลายคนได้**: ช่อง porter เช่น `"Chatchai, Maleekee"` ถูกแยกเป็น
  `porters: ['Chatchai','Maleekee']` — นับเคสต่อคนได้ถูกต้อง
- **เคส ETC** (ยกของ/เก็บเคาน์เตอร์ ไม่มีเที่ยวบิน) รองรับแล้ว
- **วันหยุดของพนักงาน**: ชีทมาร์กพื้นหลังสีแดง (`** RED MARK = DAY OFF`) →
  อ่านสีพื้นหลังมากรองออก เหลือเฉพาะ **คนที่มาทำงานจริง**
- **แท็บ "📊 สรุป" ใหม่** (`GET ?action=summary`):
  รวมทั้งวัน / ARR / DEP · สถานะ STANDBY–ON PROCESS–COMPLETED ·
  เคสที่ยังไม่ assign · กำลังคน (มาทำงาน/วันหยุด/เคสต่อคน) ·
  แยกตามประเภท Services · แยกตามสายการบิน · เคสต่อคน
- **บอร์ด LP บนหน้าหลัก** เรียงเคส **"ยังไม่ assign" ขึ้นก่อน** แล้วตามด้วย
  STANDBY → ON PROCESS → COMPLETED
- **รับเคสตามคิว** หยิบเคสที่ยังไม่มีคน assign ก่อนเป็นอันดับแรก
- ตาราง `ROMAN` แก้ให้ตรงกับที่ชีทสะกดจริง (Ratchaphol, Taofi, Ausman,
  Pongsaton, Thirasak/Theerasak, CHALOEMKIAD, PIYATHAT, JIRAWAT ฯลฯ)

## แจ้งซ่อมรถเข็น (v3.4)

- **กดค้าง** ที่คันไหนในหน้าเลือกรถเข็น (หรือคลิกขวาบนคอม) → หน้าต่างแจ้งซ่อม
  ใส่อาการได้ เช่น "ล้อหลวม / เบรกไม่อยู่"
- คันที่แจ้งซ่อมจะขึ้นสีแดง ขีดฆ่าเลข **เลือกใช้งานไม่ได้ทุกเครื่อง**
  (ฝั่ง GAS ก็กันไว้อีกชั้น — `handleStart` จะปฏิเสธถ้าคันนั้นแจ้งซ่อมอยู่)
- กดที่คันที่ซ่อมอยู่ → แจ้ง **"ซ่อมเสร็จ ✓"** กลับมาใช้งานได้
- หน้าหลักมีช่องสถิติ **🔧 ซ่อม** และหน้าเลือกรถเข็นมี filter `🔧 ซ่อม`
- เก็บใน sheet **`WCStatus`** (รถเข็น / สถานะ / อาการ / แจ้งโดย / แจ้งเมื่อ)
  แถวเก่าเก็บไว้เป็นประวัติ แถบสีแดง=ซ่อม เขียว=ใช้งานได้

## รายชื่อคนทำงานวันนี้ + เคสที่ LP assign (v3.3)

- อ่านบล็อก **STAFF RECORD** (NO./SKED/NAME/CASE SUMMARY) ในแท็บรายวันของ
  Porter Summary → ได้รายชื่อ "คนที่มาทำงานวันนั้น" (`GET ?action=staff`)
- หน้าเลือกพนักงาน + หน้าเพิ่มคิว แสดง **เฉพาะคนที่มาทำงานวันนี้** เป็นค่าเริ่มต้น
  (กด "รายชื่อทั้งหมด" เพื่อดูครบ 76 คน)

  แตะเคส = เริ่มงานด้วยคนที่ LP assign + เคสนั้นทันที
- ปุ่ม **"👥 เติมคิวจากรายชื่อวันนี้"** ในหน้าคิว — ดึงคนทั้งกะเข้าคิวทีเดียว

## Auto-deploy ขึ้น Apps Script

merge เข้า `main` เมื่อไหร่ GitHub Actions จะ push โค้ดขึ้น Apps Script ให้เอง
(workflow: `.github/workflows/deploy-gas.yml`) — ก่อนใช้ ตั้งค่าครั้งเดียว 3 ขั้น:

1. **เปิด Apps Script API** ที่ https://script.google.com/home/usersettings
2. บนเครื่องตัวเอง รัน `npx @google/clasp login` แล้วเปิดไฟล์ `~/.clasprc.json`
   คัดลอกเนื้อหา**ทั้งไฟล์**
3. เพิ่ม Secrets ที่ repo → Settings → Secrets and variables → Actions:

   | Secret | ค่า |
   |---|---|
   | `CLASPRC_JSON` | เนื้อหาไฟล์ `~/.clasprc.json` จากข้อ 2 |
   | `GAS_SCRIPT_ID` | Script ID (Apps Script → ⚙ Project Settings) |
   | `GAS_DEPLOYMENT_ID` | *(แนะนำ)* Deployment ID ของ Web App — ตั้งแล้ว URL `/exec` เดิมได้โค้ดใหม่ทันที |

workflow จะ **ตรวจ syntax ของ `Code.gs` และ `Index.html` ก่อน** ถ้าพังจะหยุด ไม่ push
ของเสียขึ้น production · ถ้าไม่ตั้ง `GAS_DEPLOYMENT_ID` โค้ดใน editor จะอัปเดต
แต่ Web App ยังเสิร์ฟเวอร์ชันเดิมจนกว่าจะกด Deploy เอง

> `appsscript.json` ใน repo คือ manifest ของโปรเจกต์ (Asia/Bangkok, V8,
> Web App: execute as me / anyone) — แก้ที่นี่แล้ว deploy ตามปกติ

## วิธีติดตั้ง / อัปเดต

1. เปิดไฟล์ "WC Tracker Log" → Extensions → Apps Script
2. วาง `Code.gs` ทับของเดิม และวาง `Index.html` ในไฟล์ HTML ชื่อ `Index`
3. Run `setupSheets()` (ครั้งแรก) — อนุญาตสิทธิ์ Sheets + Drive
4. Run `listPorterTabs()` แล้วดู Execution log:
   - ถ้าเจอ `✅ Today tab resolved` = พร้อมใช้
   - ถ้าไม่เจอ ให้ดูชื่อ tab ใน log แล้วใส่รูปแบบชื่อใน `PORTER_TAB_OVERRIDE`
5. Run `testFlights()` / `testCases()` เช็คว่าดึงข้อมูลวันนี้ได้
6. Deploy → New deployment → Web App (Execute as **Me**, access **Anyone**)
7. เอา URL ไปใส่ `GAS_URL` ใน `Index.html` แล้ว deploy ใหม่อีกครั้ง
